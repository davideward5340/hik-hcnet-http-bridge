# Windows 全量升级

将新版 `hikbridge.zip` 解压到独立的新目录，然后右键 `升级.bat`，选择“以管理员身份运行”。新目录不能与旧安装目录相同，也不能互相包含。无需填写旧安装路径，工具从已注册的服务启动命令获取路径。

`升级.bat` 必须和 `hik-bridge-upgrade.exe`、主程序、`config.json`、`version.json`、`windows-service.cmd`、SDK 和 FFmpeg 一起使用，不能只复制批处理文件。工具不依赖 PowerShell、WMIC 或 curl。

## 执行行为

升级工具在检查新包和读取旧服务状态之前取得全局跨进程互斥锁，直到升级、验证或回滚结束才释放。同机再次启动升级工具（包括 /check）会立即提示已有升级正在执行。异常遗弃的锁会报告上次升级中断，要求先检查备份和服务状态。

1. 查询 `hikbridge`、`HikSdkHttpBridge` 服务，结合可执行文件名、PE 的 CLR 标记和服务运行参数识别 C++ 原生服务或 C# 服务。多个注册、未知程序、自定义账户或残留计划任务会中止自动升级。
2. 校验新程序和配置，将新目录的**全部文件及子目录**复制到安装目录旁的临时目录，并逐文件比较。此时旧服务继续运行。
3. 导出旧服务的注册表备份。停止旧服务并等待进程退出，将旧安装目录整体重命名为旁边的备份目录，再把新目录放回原安装路径。新配置完整覆盖旧配置，旧日志、配置、缓存和程序都保留在旧目录备份中。
4. C# 服务在文件复制及校验完成后才删除。随后调用新目录中的 `windows-service.cmd install /nopause`，注册或更新为 C++ 原生服务。
5. 验证新服务为普通自动启动且正在运行，监听端口归属该服务进程，`/healthz` 正常，`/version` 与新包一致。
6. 失败时尝试恢复整个旧目录、服务路径、账户、启动方式、失败恢复策略和原运行状态。失败的新目录也会保留，便于排查。

支持内置账户 LocalSystem、LocalService、NetworkService。无法获取自定义账户密码，因此不会自动迁移这类服务。仅使用计划任务启动的旧版不属于此工具的服务迁移范围。

## 检查与日志

管理员 CMD 中运行 `升级.bat /check` 可执行预检查，不停止、删除或注册服务，也不进行目录替换。`升级.bat /nopause` 执行升级后不等待按键，适用于管理员自动化调用。

备份位于旧安装目录的同级目录，名称包含 `.upgrade-...-backup`；服务注册备份为同级 `.reg` 文件。安装脚本输出写入新目录中的 `upgrade-install.log`，回滚后可在 `.upgrade-...-failed` 目录查看。日志中报告升级和回滚结果。

程序不会按进程名称批量强杀，也不会递归删除旧目录。若文件被其他进程占用、磁盘空间不足、服务删除迟迟未完成，升级会报错并尝试回滚；回滚失败时会明确打印备份路径，请保留相关目录后人工恢复。

## 验证

`tests/windows-upgrade-unit.cpp` 覆盖路径隔离、中文及特殊字符参数、PE 识别、全量复制和目录恢复。`tests/windows-upgrade-integration.py` 使用专门的测试服务名验证 C++ 升级、C# 同名/异名迁移及启动失败回滚，不操作真实的 `hikbridge` 服务。集成测试必须以管理员身份运行。
